## Perbaikan sekelas di luar temuan terukur

Ditemukan saat memperbaiki temuan di atas; dicatat di sini karena melewati bukti pengukuran awal.

1. **`errorResponse` melempar objek biasa, bukan `createError`.** Semua jalur melempar status 500 (diverifikasi dengan PATCH tanpa autentikasi). Kini `server/utils/response.ts` melempar `H3Error` sungguhan sehingga 401/403/404/409 terbaca klien.
2. **`PATCH /api/tickets/:id/worklogs/custom` rusak di runtime.** `.set()` hanya memuat kolom yang tidak dikenal drizzle; druler diamkan kunci asing, sehingga SQL menjadi `UPDATE ... SET` kosong. Endpoint ditulis ulang agar benar-benar menyisipkan baris ke `worklogs`.
3. **`DELETE /api/tickets/:id/members/:userId` rusak di runtime.** Drizzle `.where()` menerima `SQL`, bukan callback, dan `findFirst` menyusun `&&` pada objek `SQL` yang selalu truthy. Kini memakai `and(eq(..), eq(..))`.
4. **`server/api/reports/tickets.ts` menabrak TDZ.** `inArray` dipakai sebelum didefinisikan; disusun ulang, dan filter `workerId` kini menelusuri `assignedTo` atau keanggotaan tiket.
5. **`--color-success-hover` tidak pernah didefinikasikan.** Hover tombol sukses selalu transparan; kini #065f46 di terang dan #166534 di gelap.
6. **Token destructive/status mode gelap tidak ada.** Keluarga destructive, status, dan prioritas ditambahkan khusus mode gelap agar tidak memakai nilai terang di latar gelap.
7. **`pnpm-workspace.yaml` memuat nilai placeholder `allowBuilds`.** Semua perintah `pnpm install` gagal; diset `esbuild: false`.
8. **Pesan empty state tab master salah.** Template memakai `.value` pada ref yang sudah auto-unwrap, sehingga kata kunci pencarian/filters tidak pernah muncul di pesan. Diperbaiki pada keempat blok pesan.
9. **`seedTickets()` tidak mengembalikan apa pun** sedangkan pemanggilnya memetakan hasilnya; `server/database/run-seed.ts` sudah benar, `server/database/seed.ts` disamakan.
10. **Kunci kolom mati di tujuh endpoint** (`createdByName`, `assignedToName`, `performedByName`, `workerName`, `uploadedByName`, `resolutionSummary`, `confirmedByUser`) dihapus; druler diamkan, tapi menipukan pembaca kode.
11. **Skrip `scripts/*` menerima `process.env.DATABASE_URL` yang bisa `undefined`.** Kini gagal cepat dengan pesan jelas; `smoke-org.ts` menjaga `pair` hasil split.
12. **`ITDashboard` memakai `activityCount` tanpa prop-nya.** Prop dideklarasikan dengan bawaan 0; perilaku tampilan identik dengan sebelumnya (badge tetap tersembunyi).

## Lanjutan 2026-10-17: pemeriksaan mode gelap diperluas

Penilaian sendiri menemukan cakupan uji mode gelap terlalu sempit, lalu diperbaiki. **Temuan baru: 3** (semua diperbaiki).

### Kekurangan yang ditemukan pada uji sebelumnya

1. **Cakupan halaman sempit.** `contrast-check.ts` lama hanya mengukur 4 keadaan (login, tracking, master org, master akun); setelah diganti tema hanya 3. Delapan tampilan lain (Tiket Saya, Dashboard, Pekerjaan Saya, Log Harian, Laporan, Pengaturan, form buat tiket, detail tiket) tidak pernah terukur di mode mana pun. Modal admin tidak pernah terukur karena sampling melewatkan elemen tersembunyi.
2. **Jalur persistensi tidak diuji saat gelap.** Klik-tembus selalu memuat ulang setelah tema dikembalikan, sehingga jalur plugin (localStorage → kelas `.dark` sebelum render) tidak pernah diuji dalam mode gelap.
3. **Tidak ada pembuktian token dihitung ulang.** Tidak ada yang membaca `--color-primary` sebelum/sesudah ganti tema; kegagalan `refreshThemeTokens()` bisa lolos diam-diam.
4. **Baseline diambil di halaman login.** Preferensi server diterapkan `initApp` *setelah* login, jadi arah tema di halaman login bisa berbeda dari sesudahnya. Baseline yang salah membuat label mode keliru dan toggle mengklik tombol yang tidak ada.

### Perbaikan pada uji (`scripts/contrast-check.ts`)

- Mengukur **semua tab** (8), form buat tiket, detail tiket, dan modal Tambah Perusahaan/Divisi pada **kedua arah tema**: 486 → **2198 elemen**.
- Halaman login diukur pada kedua arah lewat localStorage + muat ulang (jalur plugin).
- Muat ulang dijalankan **saat mode aktif**, lalu kelas `.dark` dan token diverifikasi bertahan.
- Token `--color-primary` dibaca sebelum/sesudah ganti tema; perubahan wajib terbukti.
- Baseline diambil **setelah** login (saat `initApp` sudah menerapkan preferensi server).
- Pengembalian tema diverifikasi dengan ulang sampai berhasil, dan kegagalan dicatat sebagai temuan, bukan dilewati diam-diam.

### Temuan baru dan perbaikannya

1. **Warna teks hardcoded `text-gray-500`/`text-gray-600`/`text-gray-700`** di `ReportsView.vue`, `TicketDetailView.vue`, `CreateTicketView.vue` (38 situs). Pada latar `bg-muted` rasionya 4.41 di terang dan 3.03 di gelap — gagal AA di kedua arah. Diganti token `text-muted-foreground`/`text-foreground` yang mode-aware.

## Lanjutan 2026-10-17 (2): garis "putih" di mode gelap

Umpan balik: garis kartu/badge di mode gelap tampak putih dan "tidak nyambung". Probe computed-style (CDP) membuktikan sebabnya dua:

1. **`border`/`divide` tanpa warna memakai warna bawaan Tailwind v3 `gray-200` (`#e5e7eb`) yang statis di kedua mode** — 82 elemen di beranda saja, dihitung identik `rgb(229,231,235)` terang maupun gelap. Diperbaiki di `tailwind.config.js`: `borderColor.DEFAULT = var(--color-border)` (preflight kini `border-color: var(--color-border)`; `divideColor` turunan dari `borderColor`).
2. **Modifikasi alpha Tailwind (`bg-primary/5`, `border-primary/15`, dst.) tidak pernah dihasilkan untuk warna berbasis `var()`** — 200+ situs di komponen menjadi kelas mati hari ini (batas `border-primary/15` pada kartu jatuh ke warna default = garis putih tadi). Diperbaiki sekali di config dengan pola `<alpha-value>`:
   `color-mix(in srgb, var(--token) calc(<alpha-value> * 100%), transparent)`.
   `color-mix` membaca nilai var saat runtime, jadi tetap mengikuti merek perusahaan dan mode gelap tanpa mengubah format token.

Hasil terukur (probe, `/` beranda): gelap kini `color(srgb 0.2 0.2549 0.3333)` = `#334155` (60x) dan merah 15% sungguhan untuk `border-primary/15` (80x); terang `#e2e8f0`. Tidak ada lagi `#e5e7eb` di CSS hasil build.

Konsekuensi tooling: computed style Chrome atas `color-mix` berformat `color(srgb ...)`; parser warna `scripts/contrast-check.ts` (dalam-halaman dan Node) serta ekstraksi lapisan `box-shadow` diperluas mengenali format itu, lalu gerbang dijalankan ulang:

- `npx tsx scripts/contrast-check.ts`: **2316 elemen, semua lolos** kedua arah tema.
- `npx tsx scripts/clickthrough.ts`: **97/97**, 0 error console.
- `pnpm typecheck`: **0**; `npx vitest run`: **52/52**; `pnpm build`: **0**.
